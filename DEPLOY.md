# Запуск сайта с нуля — пошагово

Инструкция для человека, который никогда не поднимал сервер. Делайте по порядку, ничего не пропуская.
Всё вместе занимает примерно час, из которого полчаса — ожидание DNS.

Что получится в конце: сайт на своём домене, с замочком HTTPS, работающим личным кабинетом
(регистрация, заявки, документы, переписка с менеджером) и панелью менеджера.

Сайт состоит из двух частей:

| Что | Файлы | Где работает |
|---|---|---|
| Сам сайт | `index.html`, `*.jpg` | где угодно: бакет, сервер, любой хостинг |
| Кабинет: регистрация, вход, заявки, документы, переписка | `api.php` | только там, где выполняется **PHP** |

Object Storage (бакет) — это просто хранилище файлов: он отдаёт `index.html`, но **не выполняет `api.php`**.
Поэтому для кабинета нужен обычный сервер — шаги 2–6 ниже.

---

## Шаг 1. Купить домен

Любой регистратор: reg.ru, Timeweb, Рег.ру, nic.ru. Домен в зоне `.ru` стоит около 200–400 ₽ в год.
Проверьте, что имя свободно, оплатите — домен появится в личном кабинете регистратора.
Пока ничего в нём не настраиваем: сначала нужен сервер, чтобы было куда направлять домен.

## Шаг 2. Завести сервер в Яндекс Облаке

1. Зарегистрируйтесь на <https://console.yandex.cloud>, создайте **платёжный аккаунт**
   (новым пользователям дают пробный грант — первых месяцев хватит).
2. **Compute Cloud** → **Создать ВМ**:
   - **Образ:** Ubuntu 22.04 LTS
   - **Диск:** SSD, 10 ГБ
   - **Вычислительные ресурсы:** 2 vCPU, гарантированная доля **20 %**, 2 ГБ RAM — этого достаточно
   - **Прерываемая:** нет
   - **Публичный адрес:** есть, **статический** (иначе адрес поменяется при перезапуске)
   - **Доступ:** логин `yc-user`, вставить свой SSH-ключ (как его сделать — шаг 3)
3. Нажмите «Создать» и запишите **публичный IP-адрес** машины.
4. **Сеть → Группы безопасности** → у группы этой ВМ разрешить входящий трафик
   на порты `22`, `80`, `443` с источника `0.0.0.0/0`.

Стоит такая машина примерно 600–900 ₽ в месяц — точную сумму покажет калькулятор Яндекса.

## Шаг 3. Ключ для входа на сервер (один раз)

На своём компьютере откройте PowerShell (Windows) или терминал (Mac) и выполните:

```bash
ssh-keygen -t ed25519
```

Три раза нажмите Enter (пароль можно не ставить). Затем покажите созданный ключ:

```bash
type $env:USERPROFILE\.ssh\id_ed25519.pub
```

(на Mac и Linux: `cat ~/.ssh/id_ed25519.pub`)

Скопируйте всю строку целиком — её и надо вставить в поле «SSH-ключ» при создании машины.

## Шаг 4. Направить домен на сервер

В личном кабинете регистратора откройте настройки DNS вашего домена и создайте две записи:

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | публичный IP вашей машины |
| A | `www` | тот же IP |

Сохраните. Изменения расходятся по интернету от 15 минут до нескольких часов.
Проверить можно так — команда должна вернуть ваш IP:

```bash
nslookup ваш-домен.ru
```

Пока домен не заработал, дальше идти можно: сайт поднимется по IP, а HTTPS добавится позже.

## Шаг 5. Установить сайт одной командой

Подключитесь к серверу со своего компьютера:

```bash
ssh yc-user@ВАШ_IP
```

(на вопрос про «fingerprint» ответьте `yes`). Затем выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/s4tnx/kontur/main/deploy/setup-ubuntu.sh -o setup.sh && sudo bash setup.sh ваш-домен.ru
```

Команда сама поставит nginx и PHP, скачает сайт, включит серверный кабинет,
создаст папку для документов и — если домен уже смотрит сюда — выпустит бесплатный
сертификат HTTPS, который продлевается автоматически.

Можно сразу подключить и счётчик Метрики (номер берётся в metrika.yandex.ru):

```bash
sudo bash setup.sh ваш-домен.ru 98765432 ваша@почта.ru
```

Если домен на момент установки ещё не разошёлся по DNS, сертификат не выпустится —
скрипт скажет об этом. Через час выполните:

```bash
sudo certbot --nginx -d ваш-домен.ru -d www.ваш-домен.ru
```

## Шаг 6. Первый вход и сотрудники

1. Откройте `https://ваш-домен.ru` — сайт работает.
2. «Войти или зарегистрироваться» → **Регистрация**. **Первый зарегистрированный аккаунт
   автоматически становится администратором.** Зарегистрируйтесь сами, первым.
3. Панель менеджера открывается кнопкой «Вход для сотрудников» в кабинете или по адресу
   `https://ваш-домен.ru/#/admin`.
4. Там же вкладка **Сотрудники**: добавляете почту менеджера и ставите ему роль «менеджер».
   Менеджер регистрируется на сайте сам, вы только выдаёте ему роль.

Встроенный логин `admin` работает только в демо-версии без сервера. На сервере вход — обычным аккаунтом.

## Что делать дальше

**Обновить сайт после новых правок:**

```bash
sudo bash /var/www/kontur/deploy/update.sh
```

База, документы и номер счётчика Метрики при обновлении сохраняются.

**Резервная копия** — сохраняйте эти два файла, в них всё:

```bash
sudo tar czf ~/kontur-backup-$(date +%F).tgz -C /var/www/kontur kontur.sqlite uploads
```

(`kontur.sqlite` — аккаунты, заявки и переписка, `uploads/` — документы клиентов.)

**Почта и поиск:** добавьте сайт в Яндекс Вебмастер (подтверждение — счётчиком Метрики в один клик)
и создайте карточку в Яндекс Бизнесе, чтобы сайт находили в поиске и на картах.

## Запасной вариант: бакет Object Storage + Supabase

Если сервер не нужен вовсе: сайт кладётся в бакет, а аккаунты берёт на себя Supabase.

1. **Object Storage** → создать бакет → доступ на чтение объектов: **публичный**.
   Для своего домена имя бакета должно совпадать с доменом: `kontur-doma.ru`.
2. Вкладка **Веб-сайт** → «Хостинг» → главная страница `index.html`, страница ошибки `index.html`.
3. Загрузить `index.html` и все `*.jpg` в корень бакета. `api.php` загружать не нужно — он там не работает.
4. Аккаунты: выполнить `supabase.sql` в своём проекте Supabase и вписать в начало скрипта в `index.html`
   `const SB_URL='…';const SB_ANON='…';`
5. Домен: CNAME `www` → `имя-бакета.website.yandexcloud.net`, для корня домена — запись ANAME/ALIAS
   в Cloud DNS. HTTPS: заказать сертификат в Certificate Manager и привязать его к бакету.

Загрузка файлов из командной строки:

```bash
aws --endpoint-url=https://storage.yandexcloud.net s3 cp index.html s3://ИМЯ-БАКЕТА/ --content-type "text/html; charset=utf-8"
```

**Важно:** в заявках лежат ФИО, телефон и адрес участка — это персональные данные, и по 152-ФЗ
база должна храниться в России. Supabase хранит данные в ЕС и США, поэтому для рабочего сайта
с настоящими клиентами это не подходит — берите вариант с сервером в Яндекс Облаке.

## Чего делать не стоит

Сайт в бакете, а `api.php` — на отдельной машине: это два разных адреса, браузер заблокирует запросы
(CORS). Держите сайт и кабинет на одной машине.

Serverless Containers и Cloud Functions тоже не подойдут без переделки: у них временная файловая
система, SQLite-база и загруженные документы будут пропадать после перезапуска.
