# Размещение сайта в Яндекс Облаке

Сайт состоит из двух частей:

| Что | Файлы | Где работает |
|---|---|---|
| Сам сайт | `index.html`, `*.jpg` | где угодно: бакет, ВМ, любой хостинг |
| Кабинет: регистрация, вход, заявки, документы | `api.php` | только там, где выполняется **PHP** |

Object Storage (бакет) — это просто хранилище файлов: он отдаёт `index.html`, но **не выполняет `api.php`**.
Поэтому вариантов два.

---

## Вариант 1. Виртуальная машина — всё в одном месте (рекомендую)

Работает и сайт, и аккаунты. Ставится одной командой.

### 1. Создать машину
Консоль Яндекс Облака → **Compute Cloud** → **Создать ВМ**:

- **Образ:** Ubuntu 22.04 LTS (или 24.04)
- **Диск:** SSD, 10 ГБ хватает с запасом
- **Платформа:** 2 vCPU, гарантированная доля 20 %, 2 ГБ RAM — минимальной конфигурации достаточно
- **Прерываемая:** нет
- **Публичный адрес:** есть (лучше сразу статический — тогда он не поменяется при перезапуске)
- **Доступ:** логин `yc-user`, вставить свой SSH-ключ

### 2. Открыть порты
Сеть → **Группы безопасности** → у группы этой ВМ разрешить входящие:
`22` (SSH), `80` (HTTP), `443` (HTTPS) — источник `0.0.0.0/0`.

### 3. Установить сайт
Подключиться к машине и выполнить:

```bash
ssh yc-user@ПУБЛИЧНЫЙ_IP
curl -fsSL https://raw.githubusercontent.com/s4tnx/kontur/main/deploy/setup-ubuntu.sh -o setup.sh
sudo bash setup.sh ваш-домен.ru      # без домена просто: sudo bash setup.sh
```

Скрипт ставит nginx и PHP, забирает сайт из репозитория, включает серверный кабинет
(`const API_URL='/api.php';`), создаёт папку `uploads` и настраивает лимит файла 25 МБ.

### 4. Домен и HTTPS
В DNS домена сделать A-запись на публичный IP машины, затем:

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ваш-домен.ru
```

Сертификат бесплатный и продлевается сам. **Без HTTPS пароли идут по сети открытым текстом** —
домен и сертификат лучше сделать сразу.

### 5. Первый вход
Открыть сайт → «Войти или зарегистрироваться» → **Регистрация**.
Первый зарегистрированный аккаунт автоматически становится администратором.
Дальше: панель менеджера → **Сотрудники** → почта аккаунта + роль «менеджер».

### 6. Обновление сайта
После нового коммита в репозитории:

```bash
sudo bash /var/www/kontur/deploy/update.sh
```

База и загруженные документы при обновлении не трогаются.

### 7. Резервная копия
Всё, что нужно сохранять, лежит в двух местах:

```bash
sudo tar czf ~/kontur-backup-$(date +%F).tgz -C /var/www/kontur kontur.sqlite uploads
```

(`kontur.sqlite` — аккаунты и заявки, `uploads/` — документы.)

## Вариант 2. Бакет Object Storage + Supabase

Если хочется остаться на бакете — сайт кладётся в бакет, а аккаунты берёт на себя Supabase
(бесплатно, свой сервер не нужен).

1. **Object Storage** → создать бакет → доступ на чтение объектов: **публичный**.
2. Вкладка **Веб-сайт** → «Хостинг» → главная страница `index.html`, страница ошибки `index.html`.
3. Загрузить `index.html` и все `*.jpg` в корень бакета. `api.php` загружать не нужно — он там не работает.
4. Аккаунты: выполнить `supabase.sql` в своём проекте Supabase и вписать в начало скрипта в `index.html`
   `const SB_URL='…';const SB_ANON='…';`
5. Свой домен — через CNAME на адрес бакета; HTTPS-сертификат добавляется в разделе бакета «Веб-сайт».

Загрузка файлов из командной строки (если удобнее, чем через консоль):

```bash
aws --endpoint-url=https://storage.yandexcloud.net s3 cp index.html s3://ИМЯ-БАКЕТА/ --content-type "text/html; charset=utf-8"
aws --endpoint-url=https://storage.yandexcloud.net s3 cp . s3://ИМЯ-БАКЕТА/ --recursive --exclude "*" --include "*.jpg"
```

## Чего делать не стоит

Сайт в бакете, а `api.php` — на отдельной машине: это два разных адреса, браузер заблокирует запросы
(CORS), придётся дописывать заголовки в `api.php`. Проще держать сайт и кабинет на одной машине (вариант 1)
либо целиком уйти в Supabase (вариант 2).

Serverless Containers и Cloud Functions тоже не подойдут без переделки: у них временная файловая система,
SQLite-база и загруженные документы будут пропадать после перезапуска.
